Node là gì?

ComfyUI biểu diễn pipeline bằng node-graph: mỗi node khai báo inputs, outputs và thao tác của nó; bạn nối chúng lại để tạo pipeline có thể kiểm tra và tái sử dụng.

Cần biết trước

Bài này bắt đầu phần Generation Setup. Cần hoàn thành đầy đủ phần Training — đặc biệt Bài 3.4 (Validate & Export Checkpoint) — trước khi tiến hành generation workflow.

← Xem lại bài trước: Validate & Export Checkpoint (3.4)

Định nghĩa

Node là một hộp chức năng có cổng vào (inputs) và cổng ra (outputs). Dữ liệu chảy từ node này sang node kia qua các đường kết nối gọi là edges. Toàn bộ chuỗi node đó tạo thành một workflow.

Loader

Load Checkpoint

Ví dụ node lõi cho checkpoint tương thích; outputs cụ thể phụ thuộc node và gói model đang cài.

Encoder

CLIP Text Encode

Ví dụ node lõi: mã hoá prompt thành CONDITIONING. Video model có thể dùng text encoder/node khác.

Sampler

KSampler

Chạy quá trình denoising. Nhận MODEL + CONDITIONING + LATENT, trả về LATENT mới.

Decoder

VAE Decode

Chuyển LATENT thành ảnh pixel (IMAGE) bằng Variational Autoencoder.

Output

Save Image

Lưu IMAGE ra file. Không có cổng ra — đây là điểm cuối của pipeline.

02 / 04

Kết nối & Kiểu dữ liệu

Mỗi edge (đường nối) mang một kiểu dữ liệu cụ thể. Hai cổng chỉ kết nối được khi kiểu dữ liệu khớp nhau.

Kiểu Từ node Đến node Mô tả ngắn
MODEL Load Checkpoint KSampler Weights của UNet / Diffusion model
CLIP Load Checkpoint CLIP Text Encode Encoder ngôn ngữ để xử lý prompt
CONDITIONING CLIP Text Encode KSampler Embeddings điều hướng denoising
LATENT Empty Latent / KSampler KSampler / VAE Decode Biểu diễn nén trong không gian latent
VAE Load Checkpoint VAE Decode / VAE Encode Encoder–Decoder nén/giải nén pixel
IMAGE VAE Decode / Load Image Save Image / Preview Tensor ảnh pixel [B,H,W,C]
▸ Tại sao kiểu dữ liệu quan trọng?
ComfyUI kiểm tra type tại runtime. Nếu bạn cắm nhầm cổng (ví dụ: nối IMAGE vào chỗ cần LATENT), workflow sẽ báo lỗi ngay thay vì chạy sai âm thầm. Màu sắc của dây nối trong giao diện phản ánh kiểu dữ liệu — cùng màu = kết nối được.

03 / 04

Workflow JSON

Frontend lưu graph canvas trong JSON để chia sẻ hoặc tái sử dụng. Để chạy qua API, hãy export riêng Save (API Format); hai định dạng phục vụ hai mục đích khác nhau.

Cấu trúc

Trong API format, node thường được đặt dưới key id và dùng class_type cùng inputs. Giá trị input có thể là hằng số hoặc tham chiếu output khác. Trường metadata/canvas là dữ liệu của frontend, không phải contract để automation dựa vào.

workflow.json — cấu trúc cơ bản JSON 
{
  "1": {                          // id của node
    "class_type": "CheckpointLoaderSimple",
    "inputs": {
      "ckpt_name": "v1-5-pruned.safetensors"
    },
    "_meta": { "title": "Load Checkpoint" }
  },
  "6": {
    "class_type": "CLIPTextEncode",
    "inputs": {
      "text": "a cat in a forest",
      "clip": ["1", 1]   // [node_id, output_index]
    }
  },
  // ... thêm các node khác
}

Tham chiếu đến output của node khác được viết dạng ["node_id", output_index]. Ví dụ ["1", 1] nghĩa là "lấy output thứ 2 (index 1) của node có id là 1" — tức là cổng CLIP từ Load Checkpoint.

▸ Cách Export và Import Workflow JSON
Export: Dùng Save để lưu workflow cho canvas; dùng Save (API Format) khi cần payload thực thi.

Import: Kéo thả file .json vào canvas, hoặc dùng nút Load. ComfyUI sẽ tái tạo toàn bộ sơ đồ node chính xác.

04 / 04

API Format

API Format là graph thực thi mà frontend xuất ra để gửi tới endpoint prompt của server. Nó phù hợp với automation, nhưng node khả dụng và input hợp lệ vẫn phụ thuộc phiên bản ComfyUI, custom node và model đã cài trên máy đích.

Workflow JSON thông thường

Dùng trong giao diện / chia sẻ

  • Lưu trực tiếp từ canvas
  • Giữ thông tin để frontend dựng lại canvas
  • Import/Export qua giao diện ComfyUI
  • Không nên coi là payload API ổn định

API Format

Dùng để chạy tự động / lập trình

  • Export bằng cách bật Dev mode → Save (API Format)
  • Tập trung vào node id, class_type và inputs
  • Gửi qua HTTP POST tới /prompt
  • Phù hợp cho script, queue worker và automation
Gửi request API — Python Python 
import requests, json

workflow_api = json.load(open("workflow_api.json"))

payload = {
    "prompt": workflow_api,
    "client_id": "my-script-01"
}

response = requests.post(
    "http://127.0.0.1:8188/prompt",
    json=payload
)
print(response.json())  # {"prompt_id": "...", "number": ...}

Khi server nhận job, phản hồi có thể chứa prompt_id cùng lỗi theo node. Theo dõi bằng WebSocket hoặc history của đúng deployment; đường dẫn/khả năng có thể khác giữa local và Cloud.

Kiểm tra hiểu biết

Checkpoint

3 câu hỏi nhanh để củng cố những gì vừa học.

1. Trong Workflow JSON, cú pháp ["1", 0] trong trường inputs có nghĩa là gì?

✓ Chính xác! ["node_id", output_index] — phần tử đầu là id, phần tử sau là vị trí cổng ra (bắt đầu từ 0).
Chưa đúng. Cú pháp là ["node_id", output_index]: "1" là id của node nguồn, 0 là cổng ra đầu tiên của node đó.

2. Điểm khác biệt chính giữa Workflow JSON thông thường và API Format là gì?

✓ Đúng! API Format tập trung vào graph thực thi. Hãy export lại từ đúng frontend/version thay vì tự suy ra payload từ dữ liệu canvas.
Chưa đúng. Cả hai đều là JSON, nhưng payload API là graph thực thi do frontend export; node và input hợp lệ còn phụ thuộc installation đích.

3. Node nào trong workflow chuẩn KHÔNG có cổng ra (output port)?

✓ Chính xác! Save Image là điểm cuối (terminal node) — nhận IMAGE và ghi ra file, không có output cho node nào tiếp theo.
Chưa đúng. Save Image là node cuối cùng, nhận IMAGE từ VAE Decode và không có cổng ra nào. KSampler và VAE Decode đều có outputs.

01

ComfyUI = node-graph. Mỗi node là một bước xử lý độc lập; dữ liệu chạy theo chiều các đường kết nối (edges).

03

Workflow JSON lưu toàn bộ sơ đồ. Tham chiếu giữa node dùng cú pháp ["node_id", output_index].

04
